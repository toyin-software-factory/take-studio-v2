# Launch security review: public API, MCP and OAuth sign in

**Verdict: safe to launch, with two small fixes made in this PR and a short list of bigger items for Michael.** No way was found to read or change another creator's take, to reuse a token after a disconnect, to see a key, token or link in a log, or to get a secret out of an error body.

Reviewed on 2026-11-14 on branch `b2-t101-security-review`, main at `983346e`, for rows 13 (public API, spec 0018) and 14 (MCP and OAuth, spec 0019). It was a read of the code and its tests, plus the Better Auth OAuth provider's own defaults in `node_modules`. Synthetic data only, no production sign in (C-31), no env values read or printed. Playwright cannot run in this sandbox, so browser specs were read, not run.

## Bigger items for Michael

1. **Done in B2-T103: unknown bearer values are now rate limited per address.** Each address may send 30 wrong or malformed bearer values a minute, then gets 429 with `Retry-After` before any key or token lookup. The committed failures of the address are read before any lookup; at 30 the request gets 429 with no lookup. A wrong value is counted afterwards with one atomic upsert that returns the new count, so parallel failures each get their own number, and one past 30 gets 429 instead of 401. A good request never touches the counter, so valid traffic alone can never trip the limit. The limit is shared by the address: once 30 bad values have come from it, a valid client on the same address also gets 429 until the minute ends. Deliberate trade: requests already past the read when the limit is reached still do their lookup, so a burst can overshoot by at most what one address has in flight at once. The address is stored as a hash for up to about 75 minutes (listed in the privacy table). Original finding: unknown bearer values were not rate limited. Every request with a wrong key or token costs one database write (the key lookup is an `UPDATE`) and is never counted. Guessing is not a risk (keys and tokens are 256 bits), but a flood costs database load. Suggested: a small per IP counter in front of the lookup, or a Cloudflare rate limiting rule on `/api/*` and `/mcp`. Needs a decision on where to count. **When the limit does not apply (it fails open):** a request with no `cf-connecting-ip` header has no address to count, so it is not limited (Cloudflare always sets the header in production, so this is only a local or test case). If the counter read or write fails, the request is not blocked and the lookup runs as before, so a database fault in the counter can never lock real clients out; the cost is that a flood is not limited while the counter is down.
2. **Done in B2-T104: unused OAuth clients are now cleaned up.** The `cleanup` task deletes registered clients older than 30 days with no consent and no token (`deleteUnusedOauthClients`, test in `oauth-flow.test.ts`). Original finding: registered OAuth clients were never cleaned up. Open registration, 20 an hour per IP, means unused client rows only grow. Suggested: a cleanup step in the `cleanup` task that deletes clients with no consent and no token older than 30 days. A small task of its own.
3. **Part links do not sign their length. Not being done before launch (decision: Michael).** Closing it means signing `Content-Length` for each part, which the browser upload client and the docs example (`curl` with `--data-binary`) would need to match. Today the size check at completion is the guard, and it does not limit a take that is never completed: it can hold up to part count times 5 GiB until the 6 hour backstop or idle sweep aborts it. A server side cap on stored bytes would also close it. Not before launch (Michael, B2-T103 thread).
4. **Done in B2-T104: `abort_upload` now needs `confirm: true`.** It is flagged `confirm` the way `delete_take` is, a call without it never reaches the route, and `/docs/mcp` shows "The assistant must ask you first." on both tools.
5. **Done in B2-T104: the B2-T90 leftovers.** `last_used_at` no longer moves on a 429 (`authenticateApiKey` moves nothing; `touchApiKey` runs only once the request is let through), `session_required` has one wording (`SESSION_REQUIRED_MESSAGE`), and `api-session-only.test.ts` uses typed deps. The rate window purge in batches and the `window_start` index were done in B2-T103.
6. **Real clients are still unchecked from here.** Claude.ai and other real assistants connecting end to end (step 10) cannot be run from this sandbox.
