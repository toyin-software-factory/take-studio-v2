# Verify: core take loop, spec 0004

**Verdict: PASS.** All 13 acceptance criteria are met, each with evidence from this run. Nothing failed. Three small things are worth knowing (see "Notes for the lead"); none of them breaks a criterion.

Run on 2026-11-11 against the live app (production, deploy of `49474ed`), the local app with real R2 and Trigger.dev dev (`pnpm test:pipeline`), the real handlers on a local database, and the existing tests. No personal data and no secrets are in this report or in the screenshots. It uses counts, statuses and file facts only. The production runs used one test account, and every screenshot was taken with the account menu and any other person's take hidden.

Screenshots are linked from the PR (published to the `pr-assets` branch under `S1C-T17/`): desktop at 1280 px and phone at 390 px.

## Specced surfaces

Every surface the spec names was reached in this run and works: the library page, the take page, the not found page, the upload routes (create, parts, complete), the take routes, the media route, and the `probe` and `process-take` tasks (a real take went through both on production, and through both again on the local pipeline). The data model behind them is the one the app reads and writes in those runs; I did not query the live schema separately.

## Not exercised, and why

- The live Cancel button during an upload (the file finished first); covered by the browser test above.
- A retryable failure forced on production, and a click on "Try again" there. Forcing one would mean changing production data. The pipeline run exercises the real retry end to end, and the browser test covers the button.
- A full 10 minute 1080p render timing on production (spec build step 1); that spike was recorded earlier in its own PR.
- The local app driven in the browser through a full upload. The local stack plus Chrome does not fit in this sandbox's 3 GB of memory (the app was killed, Chrome went blank). I ran the full local pipeline instead (71 checks) and drove the browser against production, plus the two refusal checks on the local app.

## Notes for the lead (not fixes in this PR)

1. **The email and the page round the removed time differently.** For the same take (2501 ms removed) the take ready email says "0:03" and the take page says "0:02", because `formatClock` in `src/lib/email/templates.ts` rounds and the one in `src/lib/take-display.ts` floors. Spec 0006 says the email shows times as the app does. Small, but a creator can see both numbers.
2. **Spec 0004 AC-1 says a signed out `/` shows the existing sign in page.** Since the sign in work, `/` is a short landing page with a "Sign in" link and the form lives at `/sign-in`. The wording is stale; nothing is wrong. For `/architect` when convenient.
3. **Test data on the production test account**: the clips from this run (two ready takes, one failed take) expire with the normal 30 day retention. Delete them from the take pages if you want them gone sooner.

## Worth knowing

- `pnpm test:pipeline` needs more than 3 GB of RAM if anything else is running; a first run died when the app was killed, and the harness reports that only as "fetch failed" on every check. It passed all 71 checks on a clean run (`NODE_OPTIONS` must not be set to the full memory size).
