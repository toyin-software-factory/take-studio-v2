# App routes and pages (src/app)

Next.js App Router on Workers through OpenNext (no incremental cache, so no ISR and no `revalidate`). The design gallery is in [src/components/AGENTS.md](../components/AGENTS.md), the take pages' UI in [src/components/takes/AGENTS.md](../components/takes/AGENTS.md), and what the API routes call in [src/server/AGENTS.md](../server/AGENTS.md).

## Conventions and gotchas

- Pages and routes are dynamic: each page and API route file exports `dynamic = "force-dynamic"`. Add it to a new one. Today the one exception is `api/auth/[...all]/route.ts`, which builds the Better Auth handler on each request with `getAuth()`.
- `/` is the public homepage (`HomePage` from `src/components/home/`, spec 0010) and imports no signed in component, so the library's client code (about 100 KB gzip) is not preloaded on it; a signed in visit gets a server side 307 to `/library` (so spec 0010 AC-2 "signed in `/` goes to takes" still holds, with no flash). `generateMetadata` gives the homepage its title, description, canonical and share cards (origin from `BETTER_AUTH_URL`, via `siteOrigin` in `src/lib/site.ts`; the absolute URLs are left out when it is unset). `/library` is the signed in library (`force-dynamic`, title "Your takes · Take Studio"): signed out it redirects to `/sign-in`; the sign in callbacks, the sidebar, breadcrumb and 404 links all point there, and `/sign-in` redirects a signed in visitor to `/library`. Never import `AppShell`, `TakeLibrary` or `UploadArea` from `src/app/page.tsx`: Next lists a page's whole server graph in its client manifest. The session lookup is `getSession` in `src/server/request.ts`. The 1200 by 630 share image is the static `opengraph-image.jpg` (and `twitter-image.jpg`) next to `page.tsx`. `robots.ts` and `sitemap.ts` list only `/` and keep `PRIVATE_PATHS` (`/takes`, `/library`, `/account`, `/design`, `/api/`, `/emails`, `/sign-in`) out. `/takes/[id]` signed out redirects to `/` before any lookup; signed in, a missing, foreign or malformed ID gives `notFound()`, the same styled 404 for all three so nothing leaks. `loadTake` is wrapped in React `cache`, so the page and `generateMetadata` share one lookup.
- `/account/api-keys` (spec 0018 AC-12): `force-dynamic`, noindex, signed out redirects to `/sign-in`; the page lists keys server side (`listApiKeys`, dates as ISO strings) and `ApiKeysManager` (`src/components/account/`) does create and revoke through `/api/keys`. The raw key lives only in the hook's state, never in the DOM after dismiss, storage, a URL, logs or analytics.
- `/` is the public homepage (`HomePage` from `src/components/home/`, spec 0010) and imports no signed in component, so the library's client code (about 100 KB gzip) is not preloaded on it; a signed in visit gets a server side 307 to `/library` (so spec 0010 AC-2 "signed in `/` goes to takes" still holds, with no flash). `generateMetadata` gives the homepage its title, description, canonical and share cards (origin from `BETTER_AUTH_URL`, via `siteOrigin` in `src/lib/site.ts`; the absolute URLs are left out when it is unset). `/library` is the signed in library (`force-dynamic`, title "Your takes · Take Studio"): signed out it redirects to `/sign-in`; the sign in callbacks, the sidebar, breadcrumb and 404 links all point there, and `/sign-in` redirects a signed in visitor to `/library`. Never import `AppShell`, `TakeLibrary` or `UploadArea` from `src/app/page.tsx`: Next lists a page's whole server graph in its client manifest. The session lookup is `getSession` in `src/server/request.ts`. The 1200 by 630 share image is the static `opengraph-image.jpg` (and `twitter-image.jpg`) next to `page.tsx`. `robots.ts` allows `/` and `OPENAPI_PATH` (`/api/openapi.json`, so the `/api/` disallow does not hide it) and `sitemap.ts` lists `/`, `/docs/api`, `/privacy` and `/terms`; both keep `PRIVATE_PATHS` (`/takes`, `/library`, `/design`, `/api/`, `/emails`, `/sign-in`) out. `/takes/[id]` signed out redirects to `/` before any lookup; signed in, a missing, foreign or malformed ID gives `notFound()`, the same styled 404 for all three so nothing leaks. `loadTake` is wrapped in React `cache`, so the page and `generateMetadata` share one lookup.
- `/privacy` and `/terms` (spec 0015): public, `force-dynamic`, the same for a signed in reader (no `getSession`, no redirect: a test scans the page source). The page files only call `loadLegalPage` (`src/server/legal/page.ts`: the allowance read for the fixed `PUBLIC_VIEWER`, `null` on a failed read, and the Draft banner reasons) and render the copy components in `src/components/legal/` inside `LegalPage` (reading layout: banner above the h1, "Last updated", a table of contents rail from 1024 px, one 72ch column; only `[data-legal-copy]` is hashed). Layout follows the Mobbin readings Michael collected: Contractbook, Devin wiki, Dropbox Sign NDA, Tana. Both are in `sitemap.ts` and the footer Legal column; they are not in `PRIVATE_PATHS`.
- `/insights` (spec 0016): counts only, `force-dynamic`, noindex, not in the sitemap. `isInsightsViewer` (`src/lib/env.ts`) compares the session user to `INSIGHTS_VIEWER_USER_ID`, read with `safeParse` outside the web env schema; anyone else, and a missing or bad config, gets `notFound()` (never a 500). The window comes from `?window=7d|30d|all` (bad values fall back to 30d).
- `/docs/api` and `/api/openapi.json` (spec 0018 step 6, AC-11): public, `force-dynamic`, the same for a signed in reader (no session lookup), indexable with a canonical. Both are generated from `API_REGISTRY` (`buildOpenApi` in `src/lib/api-openapi.ts`, page copy in `src/lib/api-docs.ts`), so a new route shows in the docs by being added to the registry. The JSON is cached 5 minutes. Schemas are read through a lookup passed to `buildOpenApi`; until Jim's `src/lib/api-schemas/` lands the bodies are empty. `tests/api-docs.spec.ts` covers axe, keyboard, phone width, robots and the sitemap.
- Standalone pages (sign in, link expired, not found, `error.tsx`, `global-error.tsx`) share one layout: a `header` with the Take Studio brand link (a plain `<a>` in `global-error.tsx`, which must not need the router), then a centred `main#content` with an `h1` at `text-h2`. They stay outside `AppShell` because they also show to signed out visitors. `tests/pages-v2.spec.ts` runs axe on each.
- Error pages: `error.tsx` shows fixed generic text and never `error.message` (the library throws "take list failed" and that must stay hidden), reports with `captureException`, and its Retry does `router.refresh()` then `reset()`. `global-error.tsx` must stand alone: its own `<html>` and `<body>`, its own font and `globals.css` imports, a plain button. Keep its words the same as `error.tsx`.
- Tab titles are written per page and end with "· Take Studio" (`layout.tsx` has no title template). Take titles come from `tabTitle` in `src/lib/take-display.ts`.
- Imports (ESLint): `src/app` may import `@/trigger` only as types, and may not use `@anthropic-ai/sdk`, `fluent-ffmpeg` or `ffmpeg-static`. `src/db` and `src/lib` may not import `@/app`.
- Workers: reach bindings with `getCloudflareContext({ async: true })`. Each `getAuth()` builds a new database client, so do not call it in a loop. Images are unoptimized (no image service on Workers) and fonts are fetched at build time (`src/lib/fonts.ts`).
- `api/health` answers 503 when a check fails. `api/sentry-check` is a plain 404 without the `x-sentry-check` token and throws with it (spec 0005). `src/instrumentation.ts` tags server errors with the route template, never the URL or query. The browser Sentry SDK is not in the first load: `src/instrumentation-client.ts` queues errors (`src/lib/browser-errors.ts`) and imports `src/lib/sentry-browser.ts` after the page is idle (4 s at most), then replays the queue; error boundaries report through `reportBrowserError`.
