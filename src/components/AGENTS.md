# Components (src/components, except takes/)

shadcn style components on Tailwind v4 tokens. Spec: [0009 design system v2](../../docs/specs/0009-design-system-v2/index.md) (replaces 0003). Rules and references: `design.md`. The take pages have their own file: [takes/AGENTS.md](takes/AGENTS.md).

- Colours live only in `src/app/globals.css`. No hex in any `.tsx`: `src/app/design/tokens.test.ts` fails on any `#abc` style text, and on any v1 palette value or JetBrains Mono left in `src`. The file has three layers: `@theme static` holds the design.md §2 colour, radius, shadow and easing tokens under their §2 names (`bg-bg`, `text-ink`, `bg-dark`, `border-line`, `bg-accent` is the lime); `:root` holds the other §2 tokens and the semantic names components use (`--bg`, `--text`, `--primary`, shadcn's `--background`); `@theme inline` maps those to utilities. Change a token in `globals.css`, `design.md` §2 and `src/app/design/tokens.ts` together; the test compares every §2 token with the CSS and the contrast ratios `design.md` quotes.
- Utilities that rebind inside `.stage` must use the semantic names (`bg-card`, `bg-background`, `text-muted-foreground`, `bg-hover-surface`), not the static §2 names: `bg-surface` is now the fixed `#f6f6f6` panel colour and `bg-accent` is the lime, neither follows `.stage`.
- Temporary v1 aliases, kept so pages not yet rebuilt keep working; parts 2 to 4 of design v2 delete them as they go: `--hover-surface`, `--selected-surface`, `--border`, `--border-strong`, `--primary-fg`, `--primary-hover`, `--primary-active`, `--danger*`, `--success-bg`, `--warning-bg`, `--info*`, `--disabled-*`, `--stage-*`, `--elevation-*`, the `--z-sticky`, `--z-dialog`, `--z-toast` style layer names, and the type utilities `text-display`, `text-caption`, `text-body`, `text-small` (now on the §3 scale). Times and sizes use the `mono` utility (`tabular-nums` in Inter Tight; no second font).
- The focus ring is global (`:focus-visible` in `globals.css`: 2 px, 3 px offset, colour `--focus`: ink on light, lime on the stage), and the `ui/` components repeat `focus-visible:outline-2 focus-visible:outline-offset-3 focus-visible:outline-ring`. Menus and selects use an inset offset.
- A 44 px touch target is per component: the class `pointer-coarse:min-h-11` (the checkbox uses an invisible 44 px `after:` square). A new control must add it itself; `tests/design-components.spec.ts` checks it on a phone.
- Reduced motion is one global CSS block. Components need nothing of their own.
- Stage (`stage.tsx`): the `.stage` class rebinds the semantic names to the dark set (`--color-dark`, white pill primary, lime focus), so shared `ui/` components work inside it unchanged. Use `StagePanel` and `StageLetterbox`. The lime accent is never text on white (1.1:1) and muted text is never lighter than `#4f4f4f` on white; tests assert both.
- Buttons are pills (40 and 48 px, `scale(.98)` pressed), inputs, textareas and selects have a bottom border only (48 px), tabs are pill tabs, and `Chip` is the toggle pill (`aria-pressed`). Weight 300 is only for body text at 16 px and up; the small text utilities carry 400.
- App shell (`shell/`, spec 0009 AC-4): `AppShell` is an async server component. It reads the five newest takes itself (`recentForCreator` in `src/server/takes/recent.ts`, the library's own query) and renders: a 264 px sticky `aside` ("Sidebar": logo, "Upload a take", Takes, Recent takes, user menu) from 1024 px, a sheet with the same `SidebarBody` below that (Radix dialog: focus trapped, Esc closes, focus returns to the menu button), a sticky glass top bar (`header`, min 72 px) and the skip link first. Pages pass `user` (with `id`) and, on the take page, `current` ({ title, status }) for the breadcrumb and status chip. The breadcrumb and chip are a client leaf (`breadcrumb.tsx`) reading `current-take.tsx`: the page's value first, then whatever the live take page publishes with `usePublishCurrentTake`, so a rename shows in the top bar at once. Tests that look for a take title in the page must scope to `getByRole("main")`: the sidebar and the breadcrumb show it too.
- Homepage (`src/components/home/`, spec 0010, signed out `/`): server components, one file per section, copy and numbers in `content.ts` (limits read from `MEDIA_LIMITS` and `VIDEO_RETENTION_DAYS`, never typed by hand; `content.test.ts` fails on claims about unbuilt features: review timeline, undo, agents choosing cuts, a monthly limit, an invite form), styles in `home.css` (design v2 tokens only; the resets are wrapped in `:where()` so they cannot outrank the section classes). Media are static files in `public/home/` (AVIF, WebP and JPEG at 480 and up to the source width, no upscaling; MP4 and WebM, no audio) described in `media.ts` and rendered by `Picture`; `media.test.ts` checks every file exists and the size budgets (tiles 2.5 MB, reel 8 MB). The draft's baked in card art that shows later slice features (the cut review, cut editing, the agent terminal) is deliberately left out. The client components are small and few: the FAQ accordion, `motion.tsx` (renders nothing, starts the motion), `menu.tsx`, `fan-toggle.tsx` and `reel-video.tsx`; everything else is a server component. The FAQ accordion: closed panels are `inert` only once the page has hydrated (`useSyncExternalStore`), so with scripts off a `noscript` style shows every answer and none is inert. The fixed nav has a light glass surface so it stays readable over the dark studio section. Motion (spec 0010 task 2): `home/motion.tsx` (client, renders nothing) dynamically imports `home/motion/start.ts` after hydration, so `gsap` and `lenis` are never in the first load and never on a signed in page; `imports.test.ts` fails if either is imported outside `home/motion/`, and `tests/home-motion.spec.ts` checks the library and a take page load no script containing them (and that the homepage does). `start.ts` runs: Lenis with ScrollTrigger and in page anchors (`scroll.ts`, off under reduced motion), the nav states `is-float` after 202 px and `is-dark` over `[data-theme="dark"]` sections (`nav.ts`), the intro (`intro.ts`: only the fan panel rises, by transform; the bar, headline and lead are never hidden or moved, so the first paint is the finished above the fold, spec 0010 AC-10) and the section heading word splits (`split.ts`: words in masks, the heading keeps an `aria-label`), staggered entrances for `[data-enter]` (`enter.ts`; hidden only while `html.js` is set and motion is allowed), the fan on a wheel with a 4 s loop that also holds while a card has keyboard focus, with cards off the panel taken out of the tab order and a paused fan settling its opening animation (`fan.ts`; the wheel's height and stacked cards are set in CSS for `(scripting: enabled) and (prefers-reduced-motion: no-preference)`, so `is-fan` added after hydration shifts nothing: CLS was 0.374 before, 0 after, and `tests/home-details.spec.ts` "first paint" guards it) and the reel pin and corner to full bleed expansion through `gsap.matchMedia` (`reel.ts`, 810 px and up; below that, or reduced, it is the plain inline 16:9 video). Anything that moves by itself has a labelled, keyboard operable, 44 px play or pause button: `FanToggle` (state in `motion/fan-state.ts`, held in sessionStorage for the visit, absent under reduced motion) and `ReelVideo` (a pause the visitor chooses is kept in `data-user-paused`, so the scroll driven autoplay never undoes it). The mobile menu (`menu.tsx`) is a native modal `<dialog>` with Tab wrapped inside it. The whole setup is rebuilt when the visitor turns reduced motion on or off while the page is open (`startHomeMotion` listens to the media query), in page links update the URL, and the nav stays a pill at the very bottom of the page. The reel's button sits inside the corner slot's rectangle (CSS variables set by `reel.ts`), so the clip never hides it. Reduced motion: no intro, splits, entrances, loops, scrubs or Lenis; the nav keeps its states with 0 ms transitions and the fan is a still picture. The studio floor (task 3, `motion/studio.ts`): the arc flattens (`--arc-k` 1 to 0.25, scrubbed), the pinned giant words (`is-staged` makes the block 300vh and the stage sticky; without scripts or under reduced motion the three words are one plain line), the scroll fill lines (the real text is grey at `--color-on-dark-60`, over 3:1; a white `aria-hidden` copy is revealed over it, so the words are always readable and axe never sees the old 1.7:1 unfilled colour), and the particle field. The field is asked about the browser first (`field-support.ts`, pure and unit tested: save data, `deviceMemory` under 4 GB or no WebGL means the field is skipped and the canvas keeps its own CSS glow background, and the Three.js chunk is never requested); otherwise `studio.ts` imports `motion/field.ts` (the only importer of `three`) when the section is within one viewport of entering. 24,000 points on desktop and 8,000 under 810 px, pixel ratio capped at 1.5, drawing only while the section is on screen, one still frame under reduced motion (drawn again only when the canvas is resized), and geometry, material and renderer (with its WebGL context) disposed when the page is left. The canvas carries `data-field` (`ready`, `static`, `skipped`, `disposed`), `data-field-reason`, `data-field-points` and `data-field-frames` for the tests, which pin `deviceMemory` to 8 (`tests/home-studio.spec.ts`) because a small runner reports 2. Colours come from the `--color-field-*` tokens at run time (no hex in the code). `field-bundle.test.ts` bundles the chunk with esbuild and fails over 170 KB gzip (about 132 KB). `ScrollTrigger.refresh()` runs once after the whole setup, because the pinned block changes the page height under the triggers made before it. Details (task 4): `tile-video.tsx` (client, no gsap) plays a tile's video on hover or focus with a fine pointer, at 60% in view on touch, never by itself under reduced motion, with a 44 px `h-media-toggle` button and a kept pause (`data-user-paused`); without scripts it keeps the browser's controls. `motion/details.ts` has the drift rows (810 px and up, `is-drift`), the flip counters (real number kept in an `h-sr-only` span, aria-hidden rolling digits, not built under reduced motion), the bottom edge blur (`.edge-blur`, on over dark sections except the footer, 810 px and up) and a ScrollTrigger refresh after FAQ panels move; `motion/cursor.ts` is the lime follower dot (fine pointer, motion allowed, labelled Play or Pause over `[data-cursor="play"]`). The FAQ panel opens with `grid-template-rows` 0fr to 1fr (the `noscript` style forces it open); the split CTA and the blurred footer wordmark with a lime glow are CSS only.
- Library and upload (spec 0009 AC-6): take cards are a thumbnail (radius md, grows 4% on hover over 600 ms) with the title (`text-h4`, an `h3` that is the stretched link), status chip and length under it, no card background; the upload area and the empty state sit on the `--color-surface` panel (`bg-panel`) with a dashed hairline. `tests/pages-v2.spec.ts` also holds the AC-9 checks: only `src/components/home/` may import `gsap`, `lenis` or `three` (a source scan), and the scripts a signed in page loads carry none of their code (looked for by signature in what the browser fetched).
- The `/design` gallery exists only when `NODE_ENV` is development or the Worker variable `DESIGN_GALLERY` is exactly `1`; production answers 404. `pnpm preview` and Playwright set it.
