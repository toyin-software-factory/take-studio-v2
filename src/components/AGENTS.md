# Components (src/components, except takes/)

shadcn style components on Tailwind v4 tokens. Spec: [0009 design system v2](../../docs/specs/0009-design-system-v2/index.md) (replaces 0003). Rules and references: `design.md`. The take pages have their own file: [takes/AGENTS.md](takes/AGENTS.md).

- Colours live only in `src/app/globals.css`. No hex in any `.tsx`: `src/app/design/tokens.test.ts` fails on any `#abc` style text, and on any v1 palette value or JetBrains Mono left in `src`. The file has three layers: `@theme static` holds the design.md §2 colour, radius, shadow and easing tokens under their §2 names (`bg-bg`, `text-ink`, `bg-dark`, `border-line`, `bg-accent` is the lime); `:root` holds the other §2 tokens and the semantic names components use (`--bg`, `--text`, `--primary`, shadcn's `--background`); `@theme inline` maps those to utilities. Change a token in `globals.css`, `design.md` §2 and `src/app/design/tokens.ts` together; the test compares every §2 token with the CSS and the contrast ratios `design.md` quotes.
- Utilities that rebind inside `.stage` must use the semantic names (`bg-card`, `bg-background`, `text-muted-foreground`, `bg-hover-surface`), not the static §2 names: `bg-surface` is now the fixed `#f6f6f6` panel colour and `bg-accent` is the lime, neither follows `.stage`.
- Temporary v1 aliases, kept so pages not yet rebuilt keep working; parts 2 to 4 of design v2 delete them as they go: `--hover-surface`, `--selected-surface`, `--border`, `--border-strong`, `--primary-fg`, `--primary-hover`, `--primary-active`, `--danger*`, `--success-bg`, `--warning-bg`, `--info*`, `--disabled-*`, `--stage-*`, `--elevation-*`, the `--z-sticky`, `--z-dialog`, `--z-toast` style layer names, and the type utilities `text-display`, `text-caption`, `text-body`, `text-small` (now on the §3 scale). Times and sizes use the `mono` utility (`tabular-nums` in Inter Tight; no second font).
- The focus ring is global (`:focus-visible` in `globals.css`: 2 px, 3 px offset, colour `--focus`: ink on light, lime on the stage), and the `ui/` components repeat `focus-visible:outline-2 focus-visible:outline-offset-3 focus-visible:outline-ring`. Menus and selects use an inset offset.
- A 44 px touch target is per component: the class `pointer-coarse:min-h-11` (the checkbox uses an invisible 44 px `after:` square). A new control must add it itself; `tests/design-components.spec.ts` checks it on a phone.
- Reduced motion is one global CSS block. Components need nothing of their own.
- Stage (`stage.tsx`): the `.stage` class rebinds the semantic names to the dark set (`--color-dark`, white pill primary, lime focus), so shared `ui/` components work inside it unchanged. Use `StagePanel` and `StageLetterbox`. The lime accent is never text on white (1.1:1) and muted text is never lighter than `#4f4f4f` on white; tests assert both.
- Buttons are pills (40 and 48 px, `scale(.98)` pressed), inputs, textareas and selects have a bottom border only (48 px), tabs are pill tabs, and `Chip` is the toggle pill (`aria-pressed`). Weight 300 is only for body text at 16 px and up; the small text utilities carry 400.
- App shell (`shell/`, spec 0009 AC-4): `AppShell` is an async server component. It reads the five newest takes itself (`recentForCreator` in `src/server/takes/recent.ts`, the library's own query) and renders: a 264 px sticky `aside` ("Sidebar": logo, "Upload a take", Takes, Recent takes, user menu) from 1024 px, a sheet with the same `SidebarBody` below that (Radix dialog: focus trapped, Esc closes, focus returns to the menu button), a sticky glass top bar (`header`, min 72 px) and the skip link first. Pages pass `user` (with `id`) and, on the take page, `current` ({ title, status }) for the breadcrumb and status chip. The breadcrumb and chip are a client leaf (`breadcrumb.tsx`) reading `current-take.tsx`: the page's value first, then whatever the live take page publishes with `usePublishCurrentTake`, so a rename shows in the top bar at once. Tests that look for a take title in the page must scope to `getByRole("main")`: the sidebar and the breadcrumb show it too.
- Homepage (`src/components/home/`, spec 0010, signed out `/`): server components, one file per section, copy and numbers in `content.ts` (limits read from `MEDIA_LIMITS` and `VIDEO_RETENTION_DAYS`, never typed by hand; `content.test.ts` fails on claims about unbuilt features: review timeline, undo, agents choosing cuts, a monthly limit, an invite form), styles in `home.css` (design v2 tokens only; the resets are wrapped in `:where()` so they cannot outrank the section classes). Media are static files in `public/home/` (AVIF, WebP and JPEG at 480 and up to the source width, no upscaling; MP4 and WebM, no audio) described in `media.ts` and rendered by `Picture`; `media.test.ts` checks every file exists and the size budgets (tiles 2.5 MB, reel 8 MB). The draft's baked in card art that shows later slice features (the cut review, cut editing, the agent terminal) is deliberately left out. The only client component is the FAQ accordion: closed panels are `inert` only once the page has hydrated (`useSyncExternalStore`), so with scripts off a `noscript` style shows every answer and none is inert. The fixed nav has a light glass surface so it stays readable over the dark studio section. Motion (nav pill, fan, reel, field, flip counters) is the next tasks.
- The `/design` gallery exists only when `NODE_ENV` is development or the Worker variable `DESIGN_GALLERY` is exactly `1`; production answers 404. `pnpm preview` and Playwright set it.
