# Components (src/components, except takes/)

shadcn style components on Tailwind v4 tokens. Spec: [0009 design system v2](../../docs/specs/0009-design-system-v2/index.md) (replaces 0003). Rules and references: `design.md`. The take pages have their own file: [takes/AGENTS.md](takes/AGENTS.md).

- Colours live only in `src/app/globals.css`. No hex in any `.tsx`: `src/app/design/tokens.test.ts` fails on any `#abc` style text, and on any v1 palette value or JetBrains Mono left in `src`. The file has three layers: `@theme static` holds the design.md §2 colour, radius, shadow and easing tokens under their §2 names (`bg-bg`, `text-ink`, `bg-dark`, `border-line`, `bg-accent` is the lime); `:root` holds the other §2 tokens and the semantic names components use (`--bg`, `--text`, `--primary`, shadcn's `--background`); `@theme inline` maps those to utilities. Change a token in `globals.css`, `design.md` §2 and `src/app/design/tokens.ts` together; the test compares every §2 token with the CSS and the contrast ratios `design.md` quotes.
- Utilities that rebind inside `.stage` must use the semantic names (`bg-card`, `bg-background`, `text-muted-foreground`, `bg-hover-surface`), not the static §2 names: `bg-surface` is now the fixed `#f6f6f6` panel colour and `bg-accent` is the lime, neither follows `.stage`.
- Temporary v1 aliases, kept so pages not yet rebuilt keep working; parts 2 to 4 of design v2 delete them as they go: `--hover-surface`, `--selected-surface`, `--border`, `--border-strong`, `--primary-fg`, `--primary-hover`, `--primary-active`, `--danger*`, `--success-bg`, `--warning-bg`, `--info*`, `--disabled-*`, `--stage-*`, `--elevation-*`, the `--z-sticky`, `--z-dialog`, `--z-toast` style layer names, and the type utilities `text-display`, `text-caption`, `text-body`, `text-small` (now on the §3 scale). Times and sizes use the `mono` utility (`tabular-nums` in Inter Tight; no second font).
- The focus ring is global (`:focus-visible` in `globals.css`: 2 px, 3 px offset, colour `--focus`: ink on light, lime on the stage), and the `ui/` components repeat `focus-visible:outline-2 focus-visible:outline-offset-3 focus-visible:outline-ring`. Menus and selects use an inset offset.
- A 44 px touch target is per component: the class `pointer-coarse:min-h-11` (the checkbox uses an invisible 44 px `after:` square). A new control must add it itself; `tests/design-components.spec.ts` checks it on a phone.
- Reduced motion is one global CSS block. Components need nothing of their own.
- Stage (`stage.tsx`): the `.stage` class rebinds the semantic names to the dark set (`--color-dark`, white pill primary, lime focus), so shared `ui/` components work inside it unchanged. Use `StagePanel` and `StageLetterbox`. The lime accent is never text on white (1.1:1) and muted text is never lighter than `#4f4f4f` on white; tests assert both.
- Buttons are pills (40 and 48 px, `scale(.98)` pressed), inputs, textareas and selects have a bottom border only (48 px), tabs are pill tabs, and `Chip` is the toggle pill (`aria-pressed`). Weight 300 is only for body text at 16 px and up; the small text utilities carry 400.
- App shell (`shell/`, spec 0009 AC-4): `AppShell` is an async server component. It reads the five newest takes itself (`recentForCreator` in `src/server/takes/recent.ts`, the library's own query) and renders: a 264 px sticky `aside` ("Sidebar": logo, "Upload a take", Takes, Recent takes, user menu) from 1024 px, a sheet with the same `SidebarBody` below that (Radix dialog: focus trapped, Esc closes, focus returns to the menu button), a sticky glass top bar (`header`, min 72 px) and the skip link first. Pages pass `user` (with `id`) and, on the take page, `current` ({ title, status }) for the breadcrumb and status chip. The breadcrumb and chip are a client leaf (`breadcrumb.tsx`) reading `current-take.tsx`: the page's value first, then whatever the live take page publishes with `usePublishCurrentTake`, so a rename shows in the top bar at once. Tests that look for a take title in the page must scope to `getByRole("main")`: the sidebar and the breadcrumb show it too. The user menu imports the Better Auth client only when you sign out (`import()` in `useSignOut`), so it is not in every signed in page's first load; keep `authClient` out of static imports in shell code.
- Delete account (`shell/delete-account*.ts*`, spec 0015 step 7): an item in the user menu opens `DeleteAccountDialog` (the dialog state lives in `UserMenu`, outside the menu). A stale session (`SESSION_EXPIRED`) is signed out and sent to `/sign-in?reason=delete-account`; that page and `SignInForm` show the notice and use `DELETE_ACCOUNT_RETURN` (`/library?delete-account=1`) as every callbackURL, and `UserMenu` reopens the dialog and strips the param. `tests/delete-account.spec.ts` covers desktop and phone.
- Homepage (`src/components/home/`, spec 0010, signed out `/`): server components, one file per section, copy and numbers in `content.ts` (limits read from `MEDIA_LIMITS` and `VIDEO_RETENTION_DAYS`, never typed by hand; `content.test.ts` fails on claims about unbuilt features: review timeline, undo, agents choosing cuts, a monthly limit, an invite form; the closing section has one sign in form instead), styles in `home.css` (design v2 tokens only; the resets are wrapped in `:where()` so they cannot outrank the section classes). Media are static files in `public/home/` (AVIF, WebP and JPEG at 480 and up to the source width, no upscaling; MP4 and WebM, no audio) described in `media.ts` and rendered by `Picture`; `media.test.ts` checks every file exists and the size budgets (tiles 2.5 MB, reel 8 MB). The s4 cards use the draft's shapes (trim bar `h-mini-tl`, swatches 16:9 inside the card, SRT box) but the draft's card art that shows later slice features (the cut review, cut editing, the agent terminal) is deliberately left out. The closing form (`closing-form.tsx`, client, B-T13) calls `authClient.signIn.magicLink` like `/sign-in` and reuses `sign-in-state.ts` (zod `parseSignInEmail`, the friendly messages); its field has no `name` in the no script GET to `/sign-in`, so the address never reaches a URL, and nothing logs it. The client components are small and few: the FAQ accordion, `motion.tsx` (renders nothing, starts the motion), `menu.tsx`, `fan-toggle.tsx` and `reel-video.tsx`; everything else is a server component. The FAQ accordion: closed panels are `inert` only once the page has hydrated (`useSyncExternalStore`), so with scripts off a `noscript` style shows every answer and none is inert. The fixed nav has a light glass surface so it stays readable over the dark studio section. Motion (spec 0010 task 2): `home/motion.tsx` (client, renders nothing) dynamically imports `home/motion/start.ts` after hydration, so `gsap` and `lenis` are never in the first load and never on a signed in page; `imports.test.ts` fails if either is imported outside `home/motion/`, and `tests/home-motion.spec.ts` checks the library and a take page load no script containing them (and that the homepage does). `start.ts` runs: Lenis with ScrollTrigger and in page anchors (`scroll.ts`, off under reduced motion), the nav states `is-float` after 202 px and `is-dark` over `[data-theme="dark"]` sections (`nav.ts`), the intro (`intro.ts`: the draft's load motion, spec 0010 AC-10 as amended 2026-11-13: the bar fades in, the headline words rise in masks, the lead fades and rises, then the fan panel rises; `intro-guard.tsx` sets `html.h-intro-pending` before the first paint so `home.css` hides them only while scripts run and motion is allowed, with a 3 s timer failsafe; reduced motion and no script show the text at once; keep CLS 0) and the section heading word splits (`split.ts`: words in masks, the heading keeps an `aria-label`), staggered entrances for `[data-enter]` (`enter.ts`; hidden only while `html.js` is set and motion is allowed), the fan on a wheel with a 4 s loop that also holds while a card has keyboard focus, with cards off the panel taken out of the tab order and a paused fan settling its opening animation (`fan.ts`; the wheel's height and stacked cards are set in CSS for `(scripting: enabled) and (prefers-reduced-motion: no-preference)`, so `is-fan` added after hydration shifts nothing: CLS was 0.374 before, 0 after, and `tests/home-details.spec.ts` "first paint" guards it) and the reel pin and corner to full bleed expansion through `gsap.matchMedia` (`reel.ts`, 810 px and up; below that, or reduced, it is the plain inline 16:9 video). Anything that moves by itself has a labelled, keyboard operable, 44 px play or pause button: `FanToggle` (state in `motion/fan-state.ts`, held in sessionStorage for the visit, absent under reduced motion) and `ReelVideo` (a pause the visitor chooses is kept in `data-user-paused`, so the scroll driven autoplay never undoes it). The mobile menu (`menu.tsx`) is a native modal `<dialog>` with Tab wrapped inside it. The whole setup is rebuilt when the visitor turns reduced motion on or off while the page is open (`startHomeMotion` listens to the media query), in page links update the URL, and the nav stays a pill at the very bottom of the page. The reel's button sits inside the corner slot's rectangle (CSS variables set by `reel.ts`), so the clip never hides it. Reduced motion: no intro, splits, entrances, loops, scrubs or Lenis; the nav keeps its states with 0 ms transitions and the fan is a still picture. The studio floor (task 3, `motion/studio.ts`): the arc flattens (`--arc-k` 1 to 0.25, scrubbed), the pinned giant words (`is-staged` makes the block 300vh and the stage sticky; without scripts or under reduced motion the three words are one plain line), the scroll fill lines (the real text is grey at `--color-on-dark-60`, over 3:1; a white `aria-hidden` copy is revealed over it, so the words are always readable and axe never sees the old 1.7:1 unfilled colour), and the particle field. The field is asked about the browser first (`field-support.ts`, pure and unit tested: save data, `deviceMemory` under 4 GB or no WebGL means the field is skipped and the canvas keeps its own CSS glow background, and the Three.js chunk is never requested); otherwise `studio.ts` imports `motion/field.ts` (the only importer of `three`) when the section is within one viewport of entering. The canvas sits in the flow right after the heading, inside a `.h-studio-clip` wrapper that holds all the section's content (`overflow: clip`), one screen tall with a negative bottom margin and `position: sticky; top: 0`, so the field opens below the heading and never over it (DV0-T17, as in `docs/design/home-v2.html`); the heading is two lines (muted, then white); the fragment shader has no `colorspace_fragment` include (it made the points whiter than the draft). 24,000 points on desktop and 8,000 under 810 px, pixel ratio capped at 1.5, drawing only while the section is on screen, fading to opacity 0 (scrubbed, `studio.ts`) before the section's bottom edge reaches the screen so no hard cut of particles shows past the studio floor (DV0-T15), one still frame under reduced motion (drawn again only when the canvas is resized), and geometry, material and renderer (with its WebGL context) disposed when the page is left. The canvas carries `data-field` (`ready`, `static`, `skipped`, `disposed`), `data-field-reason`, `data-field-points` and `data-field-frames` for the tests, which pin `deviceMemory` to 8 (`tests/home-studio.spec.ts`) because a small runner reports 2. Colours come from the `--color-field-*` tokens at run time (no hex in the code). `field-bundle.test.ts` bundles the chunk with esbuild and fails over 170 KB gzip (about 132 KB). `ScrollTrigger.refresh()` runs once after the whole setup, because the pinned block changes the page height under the triggers made before it. Details (task 4): `tile-video.tsx` (client, no gsap) plays a tile's video on hover or focus with a fine pointer, at 60% in view on touch, never by itself under reduced motion, with a 44 px `h-media-toggle` button and a kept pause (`data-user-paused`); without scripts it keeps the browser's controls. `motion/details.ts` has the drift rows (every width, `is-drift`: one nowrap line per row, 116% wide, as the draft; the section clips the overflow, so on a phone only part of a row shows at a time; reduced motion and no scripts keep the wrapped rows), the flip counters (real number kept in an `h-sr-only` span, aria-hidden rolling digits, not built under reduced motion), the bottom edge blur (`.edge-blur`, on over dark sections except the footer, 810 px and up) and a ScrollTrigger refresh after FAQ panels move; `motion/cursor.ts` is the lime follower dot (fine pointer, motion allowed, labelled Play or Pause over `[data-cursor="play"]`). The FAQ panel opens with `grid-template-rows` 0fr to 1fr (the `noscript` style forces it open); the split CTA and the blurred footer wordmark with a lime glow are CSS only.
- Homepage design check (`design-check --page home`, B-T08): the build matches home-v2 except on purpose: 44 px nav and button targets, the reel play and pause button (WCAG 2.2.2), muted (not 40% opacity) drift words for AA contrast, our own button and card copy, and the s4 cards without the draft's later slice art (B-T13 brought the shapes, the form and the sizes in line). Also on purpose after run 2 (B-T09): footer links keep 44 px targets (desktop footer 713 against 663 px). The s4 and s8 differences left after B-T13 are in its PR (no name or chips field in the s8 form, no agent terminal in the last s4 card). The FAQ question `h3` keeps the draft's browser size and weight (1.17em, 700) while the visible text is the `h-h4` span. Under 480 px the hero wheel is 300 px tall with 160 px cards, the phone reel has square corners 32 px under its heading, and a tile poster scales 1.04 while its video plays (B-T11; none of it under reduced motion). Do not chase those; the PR lists them.
- Homepage design check labels (B-T02): the homepage elements carry the `data-check="…"` labels of `docs/design/home-v2.tagged.html` so `tools/design-check` can compare the build with the draft. Keep every label and its exact name; they are attributes only. `Picture` (`check`), `SectionHead` (`check` prefix: `<prefix>-text`, `<prefix>-heading`) and `TileVideo` (`checks`) pass them down, and a repeated element carries a label only where the draft tags it (the first list item, the first three swatches). `s2-reel-cta` is the reel's play button, which only exists after hydration.
- Library and upload (spec 0009 AC-6): take cards are a thumbnail (radius md, grows 4% on hover over 600 ms) with the title (`text-h4`, an `h3` that is the stretched link), status chip and length under it, no card background; the upload area and the empty state sit on the `--color-surface` panel (`bg-panel`) with a dashed hairline. `tests/pages-v2.spec.ts` also holds the AC-9 checks: only `src/components/home/` may import `gsap`, `lenis` or `three` (a source scan), and the scripts a signed in page loads carry none of their code (looked for by signature in what the browser fetched).
- API keys screen (spec 0018 AC-12): `src/components/account/`. The create form locks while a raw key is on screen, so one can't be overwritten unsaved; the show-once panel takes focus on create and warns on leave (`beforeunload`); Copy falls back to selecting the read-only field when the Clipboard API is denied; Revoke reuses the `DeleteTakeDialog` pattern and returns focus to the list heading. Covered by `tests/api-keys.spec.ts`.
- API docs (`src/components/docs/`, spec 0018 AC-11): server components only. `ApiDocsPage` is the reading layout (skip link, "On this page" nav, one section per topic), `RouteTable` lists the registry groups and `UploadWalkthrough` renders the curl steps from `UPLOAD_STEPS`. Code blocks are focusable `pre` elements with an `aria-label`, so keyboard users can scroll them. All words and numbers come from `src/lib/api-docs.ts`, never typed in the components.
- The `/design` gallery exists only when `NODE_ENV` is development or the Worker variable `DESIGN_GALLERY` is exactly `1`; production answers 404. `pnpm preview` and Playwright set it.
- `src/components/record/` is the `/record` page (spec 0021). `RecordView` owns the recorder and upload hooks; `RecordSetup`, `RecordStage`, `RecordReview`, `PrompterText` and `PrompterControls` only render; `use-prompter.ts` holds the teleprompter state (position in a ref, one animation frame at a time; speed, size and the draft are kept per creator on the device; pausing the script never touches the recorder). The prompter text is the top overlay (centred, `max-w-3xl`, so it sits under a laptop lens and across the top of a phone); the controls are under the preview, not over it. Under reduced motion the text steps by line with `data-current` on the highlighted line. Shortcuts: P, Up and Down, + and -, never in a text field. The camera is released the moment a take is made (`onstop`) and asked for again on Record again, so a recording never keeps the camera light on in review. The preview is mirrored with CSS only: the recorded file is not mirrored. `tests/record.spec.ts` and `tests/record-prompter.spec.ts` use Chromium's fake camera and microphone (launch flags) and stubs the upload API and storage; real iPhone and Android runs belong to `/check verify`.
