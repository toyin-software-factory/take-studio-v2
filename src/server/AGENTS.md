# Server layer (src/server)

Creator scoped functions behind the routes in `src/app/api`. Specs: [0002](../../docs/specs/0002-data-model/index.md), [0004](../../docs/specs/0004-core-take-loop/index.md). The data functions underneath, the `Result` type and transactions are in [src/db/AGENTS.md](../db/AGENTS.md).

- Routes are thin: a `route.ts` calls a handler from `src/server/{uploads,takes}/http.ts` and exports `dynamic = "force-dynamic"`. The real dependencies (session, R2, Trigger.dev) come from the sibling `deps.ts`; tests call the handlers with injected deps.
- Each `http.ts` maps error codes to an HTTP status and a friendly message (`STATUS` and `MESSAGES`). Responses carry `cache-control: no-store`.
- Checks run in this order: Origin, then session, then ownership. Origin must equal the origin of `BETTER_AUTH_URL`. It is checked on writes (POST, PATCH, DELETE); GET list, detail and media skip it.
- Ownership lives in the query (`eq(take.creatorId, creatorId)`; cuts and renders join through the take). Media links are presigned only after the ownership check and an R2 HEAD.
- Sessions: pages read the session through `getSession()` in `request.ts`, which also sets the Sentry user to `{ id }`. API routes use `getCreator` in each `deps.ts`, which does not set the Sentry user.
- Retention is 30 days from upload completion and never extended (`VIDEO_RETENTION_DAYS`). The cleanup sweep runs every 15 minutes, so `isExpired` (`src/lib/take-media.ts`) also counts a take past `videoExpiresAt` as expired before the sweep marks it: media links answer 410 and retry answers 409 at once. A `processing` take is not expired until its job ends.
- Upload limit: 10 per creator per hour, counting failed ones (429 `rate_limited`).
- Email (spec 0006): `src/server/email/` holds the sign in limits, the signed turn off link (`/emails/off`: GET only redirects to a confirmation page, POST changes the setting, no session) and the take page switch API (`/api/account/email-prefs`, same guard and Origin check as takes). The sender and templates live in `src/lib/email/` because jobs use them too.
- Transcripts (spec 0007): `src/server/transcripts/` reads a transcript for its owner on the trimmed timeline (`getTrimmedForCreator`: words from `transcript`, removed ranges from the latest render, `take.duration_ms`, `source_fps`; `not_found` for another creator's take or no transcript) and serves `GET /api/takes/{id}/transcript/{txt|srt|vtt}` (ownership, then format: 404 before 422; `no-store`; the file body and headers come from `src/lib/transcript-download.ts`). It works on an expired take. The text is personal data: return it to the owner only, never log it.
- `POST /api/takes/{id}/transcript` is Make transcript / Try again (`makeTranscript`: Origin 403, session 401, owner 404, then 409 `job_active`, `original_gone`, `already_done`, `not_ready`; 202 `{ state: "making" }`; a trigger that throws finishes the job `trigger_failed` and answers 503). Retry answers `transcript_running` (the "still being made" message) while a transcribe job runs.
- `GET /api/takes/{id}/transcript` (session, then ownership; another creator's take is 404) returns `state`, `reason`, `canMake` and, when ready, the trimmed paragraphs and `version` (via `getTrimmedForCreator`). `state` is derived per request (transcript row, else the latest `transcribe` job). `getForCreator`'s `latestJob` ignores `transcribe` jobs so the progress view only follows video jobs.
- Backgrounds (spec 0008): `src/server/backgrounds/library.ts` (with `library-http.ts` and `library-deps.ts`) lists what a creator can pick (`GET /api/backgrounds`: `builtIn`, `mine` newest first (max 100) and `defaultId`, each item `{ id, name, alt, status, thumbUrl }` with a 1 hour presigned thumbnail). `defaultId` is an addition to the spec's response shape: the creator's last pick read from `user.default_background_id`, null when it was deleted or is not ready, so the upload area can preselect without another read. Upload create (`POST /api/uploads`) takes an optional `backgroundId` (an ID or `original`): in the creator's transaction it locks the creator, then the background (`FOR KEY SHARE`), then creates the take, and stores `take.background_id` and `user.default_background_id` together; 404 `background_not_found` for an unknown or another creator's background, 409 `background_not_ready`. Left out means no choice and no change to the default.
- Multipart upload and R2 rules: [src/server/uploads/AGENTS.md](uploads/AGENTS.md).
