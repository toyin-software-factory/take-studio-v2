# Tests (tests/ and how to run each kind)

- Unit: `pnpm test` (Vitest, only `src/**/*.test.ts`). Database tests need `pnpm db:up`. The suites that need the real ffmpeg and ffprobe with libwebp (`src/trigger/ingest-background.test.ts`, `src/background-upload.e2e.test.ts`) are skipped on a machine without them (a `SKIPPED` note prints) but fail when `CI` is set; CI installs the pinned BtbN build (see `src/trigger/AGENTS.md`).
- Suites that run the real ffmpeg go through `describeWithFfmpeg` (`src/test/ffmpeg.ts`), which gives each of their tests 30 s (`REAL_FFMPEG_TEST_TIMEOUT_MS`): Vitest's 5 s default flaked on a loaded CI runner (S3S-T12). Use it for any new real tool suite.
- Browser: `pnpm build:worker`, then `pnpm test:e2e`. It runs against a built Worker (`opennextjs-cloudflare preview` on 127.0.0.1:8787), not `next dev`, and nothing builds the Worker for you. Locally a stale preview server is reused (`reuseExistingServer`), so stop old ones. It needs Postgres: `tests/support/session.ts` seeds users and sessions and forges Better Auth's signed cookie, so the Worker must be built with the same `BETTER_AUTH_SECRET`, and non local hosts are refused. CI writes a placeholder `.env` before the build because OpenNext bundles it.
- The design specs split by mode: `design.spec.ts` and `design-components.spec.ts` skip when `E2E_PRODUCTION=1`, and the production check ("design gallery (production) > returns not found", which needs `E2E_PRODUCTION=1`) is a separate run: CI runs it in its own step after the normal e2e (the same built Worker served without `--var DESIGN_GALLERY:1`), and fails that step on any skipped test or if it did not report 1 passed, so it can never skip quietly. Locally: `E2E_PRODUCTION=1 pnpm exec playwright test tests/design.spec.ts -g "design gallery \(production\)"`.
- Pipeline: `pnpm test:pipeline` is the API level end to end check against the real R2 and Trigger.dev dev environments. It is a pre release check, not PR CI, and needs R2 and Trigger.dev keys (`harness.ts` lists them), Docker Postgres, and ffmpeg 7 with libx264 and libx265. It starts `next dev` and `trigger dev` as child processes; the root `AGENTS.md` says what to do when a failed run leaves them behind. On a 3 GB sandbox run nothing else beside it (no browser, no `NODE_OPTIONS` set to the full RAM): when the app is killed for memory the harness only prints `fetch failed` on every check. `PIPELINE_ONLY=background pnpm test:pipeline` runs only the background scenarios (`tests/pipeline/background.ts`: the built in studio, uploaded backgrounds, keyed and no green screen takes, previews, a background change, deletion; 53 checks), lighter for a small machine. A clean full run is 164 checks (the transcript checks of spec 0007 need `DEEPGRAM_API_KEY` in the shell and call real Deepgram with tiny synthetic clips, a few cents; they use their own creator because of the 10 uploads per hour limit). Results print only at the end (`check()` in `run.ts` just collects them; the ✓/✗ lines and the total come after the last scenario), so a healthy run is silent for many minutes: never stop it for silence. Judge progress by the task runs in `trigger.log` in the harness work folder (`$TMPDIR/pipeline-*`, `/tmp/pipeline-*` when `TMPDIR` is unset; `next.log` and `proxy.env` are there too, so never print `proxy.env`). The harness logs no step timings and the `job_step` rows do not survive the run, so to time a step (spec 0012) sample `job_step.started_at` and `finished_at` from the local database while the run is live. `next dev` opens a database client per request and never closes it, so the harness closes connections idle for 30 s itself and stops its servers on exit, failure or Ctrl+C; a run that still dies with "too many clients" or `trigger dev` "Worker timed out" needs the leftovers killed and `docker compose restart postgres`.
- Cut quality: `src/lib/cut-quality.test.ts` runs the invented test set in `tests/cut-quality/` (scorer, case schema, rules plus recorded model answers, floors in `baseline.json`) as part of `pnpm test`; how to add a case is in [tests/cut-quality/AGENTS.md](cut-quality/AGENTS.md).
- `legal-pages.spec.ts`: `/privacy` and `/terms` signed out and in, the Draft banner, one h1, the table of contents, axe in light and dark, heading order, contents anchors, focus order, line length, phone width and print (AC-12), and the footer links.
- `usage.spec.ts` (spec 0014 AC-9, AC-14): the meter, the low notice, the used up drop zone, the limit off, the refused upload that reads the numbers again, and the dated failed take message, desktop and Pixel 7 size, with axe. `tests/support/usage.ts` writes the two `app_setting` rows and this month's `usage_month` row for a test user (hash from `USAGE_HASH_SECRET`, which CI writes to the placeholder `.env`) and puts the settings back after each test.
- `legal-pages.spec.ts`: `/privacy` and `/terms` signed out and in, the Draft banner, one h1, the table of contents, axe in light and dark, and the footer links.
- `usage.spec.ts` (spec 0014 AC-9, AC-14): the meter, the low notice, the used up drop zone, the limit off, the refused upload that reads the numbers again, and the dated failed take message (also a take expiring before the reset, no sideways scroll, 44 px targets), desktop and Pixel 7 size, with axe. `tests/support/usage.ts` writes the two `app_setting` rows and this month's `usage_month` row for a test user (hash from `USAGE_HASH_SECRET`, which CI writes to the placeholder `.env`) and puts the settings back after each test.
- Legal launch gate: `pnpm test:legal-launch` (spec 0015 AC-8, AC-11, `tests/legal-launch/legal-launch.check.ts`, config in `scripts/`) is not part of `pnpm test` or CI. It fails until `LEGAL_ENTITY` and `REVIEW` are filled and match the live versions, page text hashes and the allowance read from `DATABASE_URL_DIRECT` (no database or a refused remote host fails it). The logic is `draftReasons`, unit tested in `src/lib/legal-facts.test.ts`.
- `PIPELINE_ONLY=ai pnpm test:pipeline` (spec 0012 task 8, `tests/pipeline/ai-edit.ts`) measures the transcript plus AI edit time and the Claude tokens on one short take and `AI_RUNS` (default 3) synthetic takes of just under 10 minutes. The long file is built at run time from `speech-en.mp4` repeated (stream copy, never committed; the text repeats, so word count is realistic and content is not). It calls the real Deepgram and the real Claude, so run it only when told to; it needs `DEEPGRAM_API_KEY`, `ANTHROPIC_API_KEY` and `LIVE_SLICE` 5. It samples `job_step` times from the database while the take exists and reads the token counts from the "ai edit answered" lines in `trigger.log`; cost needs `AI_PRICE_IN_PER_MTOK` and `AI_PRICE_OUT_PER_MTOK` (USD, not guessed). It prints `[ai-measure]` lines with numbers only, and checks AC-6 (at most 120 s added) and that tokens were logged. Agent sandboxes cannot run it: their proxy swaps the Anthropic key, so the AC-6 numbers were taken in Trigger.dev cloud with the temporary `ai-measure` task (C-15, C-29).
- `PIPELINE_ONLY=usage pnpm test:pipeline` runs only the monthly usage limit checks (spec 0014, `tests/pipeline/usage.ts`): one take charged, a hint longer than what is left refused at upload create, a second take refused at the probe and kept (no job, nothing charged, original served), retry refused with the dated message and the four numbers, then retry accepted after the allowance setting is raised and charged once. It writes the two `app_setting` rows of the local pipeline database and restores them (limit off, 3600) in a `finally`. The full run includes these checks.
- `PIPELINE_ONLY=changes pnpm test:pipeline` runs only the waveform and cut change checks (spec 0011, `tests/pipeline/changes.ts`): a waveform is stored by the initial job, none for a take with no audio, and a `POST /changes` keeping one cut renders exactly that cut as `removed_ranges`, updates the flags, charges nothing, and gives a take whose waveform was cleared (an older take) a new one. The change render's file is downloaded and its length checked, and the request waits until the take has no running job (`waitIdle` in `tests/pipeline/wait.ts`, shared with the background scenarios). The full run includes these checks.
- `PIPELINE_START=prod pnpm test:pipeline` builds the app once (`next build` with `PIPELINE_BUILD=1`, which makes `next.config.ts` skip type errors for that build only; `pnpm typecheck` runs separately) and serves it with `next start` instead of `next dev`, keeping `trigger dev` as before. `next dev` is killed by the kernel at about 1 GB on a 3 GB sandbox; the build peaks near 1.7 GB and the server stays lower, so `PIPELINE_ONLY=changes PIPELINE_START=prod pnpm test:pipeline` (24 checks) fits. `next start` runs with `--keepAliveTimeout 120000`: its 5 s default closes the harness's idle connection during the ffmpeg checks and the next request fails with `UND_ERR_SOCKET`. The build log is `next-build.log` in the run's work folder. Swap files do not work in the sandbox (`swapon` gives `Invalid argument`).
- Keying check (spec 0008): `tests/keying-check.ts` runs the synthetic green screen and no green screen clips through the real `process-take` (needs `trigger dev` with the proxy env file, `pnpm db:seed` and a local database), prints the steps, the render row and the output facts, counts green pixels in a band around the subject (there must be none) and exits 1 when any clip misses its expected outcome. Set `OUT_DIR` to keep a frame of every output. It also checks the person is kept (98 % of the subject's pixels unchanged) on `keyed-lime`, `keyed-mint` and `keyed-shadow`. The checks use the blue test only placeholder studio (`testOnly`), not the first of the six.
- Background change check (spec 0008): `tests/background-change-check.ts` processes a keyed take, changes it to a second studio, to a missing image and back to the original through the real job (needs `trigger dev` with the proxy env file and `pnpm db:seed`), checks the take stays Ready, the video only changes on success, nothing is charged, and exits 1 on a miss. `OUT_DIR` keeps a frame after each step.
- Preview check (spec 0008): `tests/preview-check.ts` asks for stills of a green screen take, a portrait take and a take with no green screen through the real `preview-background` task (needs `trigger dev` with the proxy env file and `pnpm db:seed`), prints the seconds each took, checks the picture (no green left, the studio showing, the plain frame and the flag), the cache hit, two backgrounds on one take, that two previews of one take do not overlap, and that a take deleted meanwhile leaves no row or file. Exits 1 on a miss.
- Manual checks: `tests/probe-check.ts` and `tests/process-check.ts`, run as `DATABASE_URL_DIRECT=postgres://postgres:postgres@localhost:5432/take_studio pnpm tsx tests/probe-check.ts`.
- Fixtures: `tests/fixtures/media/` is committed. Regenerate with `bash tests/fixtures/make-media.sh`, `bash tests/fixtures/make-pause-media.sh` and, for the transcript checks, `bash tests/fixtures/make-speech-media.sh` (synthetic Deepgram voices, needs `DEEPGRAM_API_KEY`) and `bash tests/fixtures/make-keying-media.sh` (synthetic green screen and no green screen clips: a person shape on #00B140 or on a wall, one still frame looped, so the files are 40 to 180 KB; 14 clips: with `keyed-lime`, `keyed-mint` and `keyed-shadow`, other greens with a grey sweater, S3S-T10); the pause fixtures depend on exact tone and flash timings written in the script comments.
- In CI Playwright retries once and `forbidOnly` is on.
- CI e2e runs in the official Playwright container image (`PLAYWRIGHT_IMAGE` in `.github/workflows/ci.yml`, `docker run --network host`), not on the runner, so no `apt-get` runs at run time (`ubuntu-latest` moved to a newer Ubuntu whose apt mirrors were unreachable and blocked every PR, so every workflow now pins `runs-on: ubuntu-24.04`; a test fails if `ubuntu-latest` returns). The tag must equal the exact `@playwright/test` version in `package.json`: bump both together, `src/ci-config.test.ts` fails the build on drift or if `apt`, `install-deps` or `--with-deps` return. Only the e2e step is in the container (the build, Postgres service and `.env` stay on the runner), and the runner's own Node (from `.nvmrc`) and `pnpm` are mounted read only into the container and put first on `PATH`: the image ships a newer Node and no `pnpm`, and the tests and the preview must run on Node 22 like everything else.
- Cut review browser tests (`tests/cut-review.spec.ts`, spec 0011): the take GET gets `cuts` injected by a route (seeded takes have a render with `removedRanges` but no cut rows), and the waveform, original link, `POST /changes` and `/jobs/*` are stubbed; Pixel 7 for the phone case. It also covers the cut list (reasons readable without undoing, list and timeline in sync, a row only seeks) and the fallback note. `tests/background-take-page.spec.ts` picks a tile and then presses Render in the pending bar (there is no "Use this background" button).
- Keyboard tests on a Radix menu must wait for a readiness signal that is set after the page's effects have run before pressing keys: Radix only learns a menu was opened from the keyboard through a document listener added in an effect, and an early Enter leaves focus on the menu instead of the first item. On the `/design` gallery that signal is `[data-overlays-ready='true']`, set by `OverlayDemos`; a menu on any other page needs its own signal. Never fix this with a sleep or a retry.
- axe checks go through `tests/support/axe.ts`: `expectNoSeriousAxeIssues` first waits for running CSS transitions and animations to finish, because a colour caught mid fade (a tab losing its selected colour) is a blend that reads as low contrast (4.45 for `#656565` on `#e1e1e1`, DV0-T14). Never lower the threshold or add a sleep; the homepage uses `expectNoSeriousAxeIssuesWhenSettled`.
